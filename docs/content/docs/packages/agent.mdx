# @homeslate/agent

Connects a home network's Home Assistant to a **hosted** homeslate API. The
hosted API runs in the cloud and can't reach `homeassistant.local`, so a small
process on the LAN dials out to a [`@homeslate/relay`](/docs/packages/relay) and
answers the generic Home Assistant entity and service calls used by every Home
Assistant widget.

If your homeslate API runs on the same home network (the
[reference app](/docs/reference) or a [self-hosted](/docs/self-hosting) install),
you don't need this — `@homeslate/server` talks to Home Assistant directly.

## Why an agent

- **Outbound only.** The agent opens the socket to the relay; nothing listens on
  the LAN, and Home Assistant is never exposed to the internet.
- **The Home Assistant token stays home.** It's read from the agent's environment
  and never sent to the relay or the cloud. The relay authenticates with a
  separate, revocable, account-bound token.

## Protocol v2

The agent and relay speak one narrow, generic protocol:

| Method | Purpose |
| --- | --- |
| `entities.list` | List entity summaries for one allowlisted domain |
| `entity.get` | Read one entity's raw state (the server applies the domain mapper) |
| `service.call` | Call an allowlisted service with allowlisted data keys |

There are no per-domain methods. The agent advertises the domains it can serve
from its `hello` (`agent.domains`, sourced from `knownDomains()`), and the relay
re-validates every request against the same registry before forwarding it. The
agent validates again before touching Home Assistant. A protocol mismatch or an
unknown domain/service/entity id is a clean reject.

The optional `fetchImage` and `history` transport methods are **direct-mode
only** today; they are not part of the agent protocol yet. In relay mode, media
artwork falls back to a placeholder and the History widget reports `501`.

## Run it

```bash
HOMEASSISTANT_BASE_URL=http://homeassistant.local:8123 \
HOMEASSISTANT_TOKEN=<home-assistant-long-lived-token> \
HOMESLATE_RELAY_URL=wss://relay.homeslate.app/agent \
HOMESLATE_ACCOUNT_ID=<account> \
HOMESLATE_AGENT_TOKEN=<relay-token-from-the-hosted-ui> \
npx @homeslate/agent
```

| Env | Meaning |
| --- | --- |
| `HOMEASSISTANT_BASE_URL` | Home Assistant origin on the LAN. |
| `HOMEASSISTANT_TOKEN` | Home Assistant long-lived access token. |
| `HOMESLATE_RELAY_URL` | Relay WebSocket URL (`wss://…/agent`). |
| `HOMESLATE_ACCOUNT_ID` | Account the agent is paired with. |
| `HOMESLATE_AGENT_TOKEN` | Revocable relay token, bound to the account. |
| `HOMESLATE_AGENT_ID` | Optional stable id for this instance. |

## Docker

Home Assistant advertises itself via mDNS, which a bridge-network container can't
resolve. Use host networking, or set `HOMEASSISTANT_BASE_URL` to the LAN IP.

```bash
docker run --network host \
  -e HOMEASSISTANT_BASE_URL=http://homeassistant.local:8123 \
  -e HOMEASSISTANT_TOKEN=… \
  -e HOMESLATE_RELAY_URL=wss://relay.homeslate.app/agent \
  -e HOMESLATE_ACCOUNT_ID=… \
  -e HOMESLATE_AGENT_TOKEN=… \
  homeslate/agent
```

## Library

```ts
import { createHomeslateAgent } from "@homeslate/agent";

const agent = createHomeslateAgent({
  relayUrl: "wss://relay.example.com/agent",
  token: relayToken,
  accountId,
  baseUrl: "http://homeassistant.local:8123",
  haToken,
});
agent.onStateChange((state) => console.log(state)); // connecting | connected | disconnected
agent.start();
```

The agent reconnects with exponential backoff (1s → 60s, ±20% jitter), heartbeats
through the relay, and only forwards the allowlisted generic methods
(`entities.list`, `entity.get`, `service.call`). It advertises the domains it
serves in its `hello`, and re-validates every request against the same domain
registry the API routes use.
